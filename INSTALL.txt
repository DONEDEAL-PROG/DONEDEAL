DONEDEAL SUPPORT AND SIMPLIFIED PIN RECOVERY

Replace all included files at matching repository paths, then deploy together. This patch is based on DONEDEAL-main (5)(2).zip. No additional SQL migration or new secret is required; keep the existing recovery tables and PIN_RECOVERY_SECRET.

Flow: Forgot PIN opens customer support with a prefilled recovery message and registers a recovery request when a browser backup exists. Customer reviews/sends the ticket. Staff independently verifies identity through the existing registered channel or in person, then selects Approve reset on the PIN recovery dashboard. Customer returns to My account on the same browser: Reset PIN appears automatically (checked on page load, focus, and every 15 seconds). Customer chooses and confirms their new PIN. No recovery code is copied from chat.

Staff must not ask for or select the new PIN. Approval expires after 15 minutes and can be redeemed once. Existing encrypted recovery backup and browser credentials are still required. This does not introduce recovery on another device.

Support conversation bubbles and reply form now have calmer neutral surfaces, readable typography, and theme-aware colors. Pink is reserved for the Send Message button.

Verification: JS syntax checks passed. Mocked API checks passed for pending, expired, wrong-browser, successful code-free redemption, and reused approval rejection. Production end-to-end recovery has not been performed.
